# 发布排期

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_dev_05_sk03` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 分发中控 |
| 能力族 | — |
| 复杂度 | `S` |
| 阶段 | `P1` |
| 复用度 | 高 |
| 资产形态 | 纯提示词（无运行时依赖） |

## 能力描述

同 4.4.1-S6

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `items` | array | ✅ | 待处理的条目列表 |

## 输出规格

排期与调度

- `schedule`：逐项时间安排
- `conflicts`：时间/资源冲突及处理方式
- `unscheduled`：受约束无法安排的条目

## 使用步骤

### 方式一：直接使用（最快）

1. 打开任意支持自定义提示词的 AI 工具
2. 复制 `prompt.txt` 的**全部内容**作为系统提示词
3. 按上方「输入规格」提供数据
4. 得到符合「输出规格」的结果

### 方式二：在主流平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |
| **Claude** | 新建 Project → Instructions → 粘贴 `prompt.txt` |
| **ChatGPT** | 新建 GPT → Instructions → 粘贴 `prompt.txt` |

## 边界（不做的事）

- ❌ 编造数据、案例或效果承诺
- ❌ 使用违反《广告法》的极限词
- ❌ 生成诱导好评、刷量、删差评等违规内容
- ❌ 执行或建议任何绕过平台规则的操作
- ❌ 涉及资金操作或代替用户做最终决策
- ❌ 处理超出本职能力范围的请求（应明确说明并建议转其他技能）

## 调用示例

**输入**：

```json
{
  "items": "待排项：\n1. 《秋季收纳好物清单（上）》小红书版，需在晚间黄金时段发布\n2. 《秋季收纳好物清单（上）》知乎版，需与小红书版间隔 30 分钟以上\n3. 《秋季收纳好物清单（上）》B站动态版，需排在三个平台的最后\n4. 《收纳改造 vlog》B站视频版，剪辑已完成，计划在 10 月 11 日发布",
  "constraints": "可用发布时段：每日 12:00-13:00、18:00-22:00；频率上限：每平台每日 1 条；小红书每周最多 5 条；10 月 10 日全天外出无法发布"
}

```

**输出**：

```markdown
## 排期表

| 日期 | 时间 | 内容 | 平台 | 状态 |
|---|---|---|---|---|
| 2026-10-09 | 20:00 | 《秋季收纳好物清单（上）》 | 小红书 | 已排入 |
| 2026-10-09 | 20:35 | 《秋季收纳好物清单（上）》 | 知乎 | 已排入 |
| 2026-10-09 | 21:10 | 《秋季收纳好物清单（上）》 | B站 | 已排入 |
| 2026-10-11 | 19:00 | 《收纳改造 vlog》 | B站 | 已排入 |

## 冲突与处理

1. 三个平台版本需错开发布：小红书 20:00 → 知乎 20:35（间隔 35 分钟，满足「间隔 30 分钟以上」约束）→ B站 21:10（排在最后），三条均落在 18:00-22:00 黄金时段内
2. 《收纳改造 vlog》原计划排在 10-11 之前，但 10-10 全天外出无法发布：将 vlog 移至 10-11 19:00 发布，符合可用时段；B站同日在 21:10 无其他排期，不违反「每平台每日 1 条」的频率上限
3. 小红书 10-09 当周（10-05 至 10-11）仅排入 1 条，未超过「小红书每周最多 5 条」的上限

## 未能排入

1. （无）全部 4 个待排项均已成功排入时间轴

---
*AI 生成内容，排期需人工确认后生效。*


```
