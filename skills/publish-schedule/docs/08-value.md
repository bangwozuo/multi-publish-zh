# 发布排期 · 解决问题与价值

## 一、问题（现状有多痛）

| 维度 | 现状 |
|------|------|
| 谁在痛 | 独立开发者、一人公司（OPC）创始人 |
| 痛在哪 | 既要做产品又要做增长，时间被切碎，内容产出断档 |
| 不解决的后果 | 内容断档 / 响应滞后 / 商机流失，且随规模放大人力缺口 |
| 现状做法 | 手工逐条处理，或干脆不做 |

## 二、解法（本资产做什么）

| 环节 | 原做法 | 用本资产后 |
|------|-------|-----------|
| 启动 | 从零想、从零写 | 复制提示词，立刻可用 |
| 执行 | 手工逐条 | AI 出初稿，人只做审核与微调 |
| 一致性 | 因人而异 | 同一套提示词，输出风格稳定 |
| 成本 | 雇佣/外包 | 零边际成本，多跑一次不多花钱 |

## 三、价值量化

| 指标 | 估算 |
|------|------|
| 首次可用时间 | 约 0.5 小时（含配置） |
| 单次任务节省 | 视场景，通常 10-60 分钟/次 |
| ROI 参考 | 按你的人力时薪换算，通常 1-2 次使用即回本 |
| 复杂度 | `S` |
| 阶段 | `P1` |

## 四、成本结构

| 项 | 成本 |
|----|------|
| 资产本身 | ¥0（Apache-2.0 开源） |
| 平台费用 | ¥0（用你自己的 AI 订阅） |
| API Key | **不需要** |
| 部署运维 | **不需要** |
| 学习成本 | 复制粘贴级（见 `01-usage-manual.md`） |

## 五、价值主张一句话

> 把「发布排期」这件事，从**「要专门找人 / 专门抽时间」**
> 变成 **「复制一段提示词，10 分钟出初稿」**。

## 六、不承诺什么（诚实边界）

- ❌ 不承诺「零人工」——AI 产出仅供参考，必须人工定稿
- ❌ 不承诺「效果翻倍」——效果取决于输入质量与人工审核
- ❌ 不承诺「替代专业判断」——法律 / 税务 / 医疗等以专业人员意见为准
